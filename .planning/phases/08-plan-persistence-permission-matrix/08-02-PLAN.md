# Plan 08-02: Central Plan, Capability, Limit, and AI Credit Matrix

**Phase:** 8 - Plan Persistence & Permission Matrix  
**Status:** Ready  
**Requirements:** PLAN-03, PLAN-04, PERM-01, PERM-04, AI-03

<objective>
Create the central TypeScript plan model that defines valid plans, defensive parsing, product-facing capabilities, commercial limits, AI monthly credits, and AI response-level credit weights.
</objective>

## Scope

In scope:
- Create a reusable plan/matrix module.
- Refactor plan provider runtime parsing to use the central module.
- Centralize landing-page commercial limits and AI response mode costs.
- Make helpers available for later UI, route, API, and AI enforcement phases.

Out of scope:
- Broad sidebar/locked component integration; Phase 9 owns that.
- Server/API enforcement of AI mode or credits; Phase 10 owns that.
- Real persisted AI credit consumption.

### 08-02-01. Create central plan matrix module

**Type:** implementation  
**Files:** `lib/plans.ts`  
**Read first:**
- `.planning/phases/08-plan-persistence-permission-matrix/08-CONTEXT.md`
- `app/page.tsx`
- `app/api/ai/route.ts`
- `components/plan/plan-provider.tsx`

**Action:**
- Create `lib/plans.ts`.
- Export:
  - `PLAN_TYPES = ["essencial", "pro", "premium"] as const`
  - `type PlanType = (typeof PLAN_TYPES)[number]`
  - `AI_RESPONSE_MODES = ["simple", "detailed", "diagnostic"] as const`
  - `type AIResponseMode = (typeof AI_RESPONSE_MODES)[number]`
  - `type CapabilityKey` including at least `ai_assistant`, `reports`, `workers`, `environmental_conditions`, `advanced_insights`, `farm_management`, and `task_management`
  - `PLAN_ORDER` where `essencial = 0`, `pro = 1`, `premium = 2`
  - `DEFAULT_PLAN = "essencial"`
  - `TRIAL_DAYS = 7`
- Export `PLAN_MATRIX` keyed by `essencial`, `pro`, and `premium`.
- Each matrix entry must include:
  - display name and price copied from landing page: Essencial `R$ 44,90/mês`, Pro `R$ 66,90/mês`, Premium `R$ 99,90/mês`
  - limits: birds, users, farms, tasks, insights, aiCreditsMonthly
  - capabilities with product-facing keys and minimum plan metadata
- Use landing-page limits:
  - Essencial: `birds: 300`, `users: 1`, `aiCreditsMonthly: 15`, `farms: 1`, `tasks: "limited"`, `insights: "basic"`
  - Pro: `birds: 1000`, `users: 2`, `aiCreditsMonthly: 30`, `farms: 2`, `tasks: "expanded"`, `insights: "advanced"`
  - Premium: `birds: null`, `users: 5`, `aiCreditsMonthly: 60`, `farms: null`, `tasks: null`, `insights: "complete"`
- Export AI mode metadata:
  - `simple`: label `Resumo simples`, description `Resposta rápida e direta`, creditCost `1`
  - `detailed`: label `Análise detalhada`, description `Dados e comparativos`, creditCost `3`
  - `diagnostic`: label `Diagnóstico com recomendações`, description `Análise completa + plano de ação`, creditCost `5`
- All plans may use all AI modes in the matrix.

**Verify:**
- `rg -n "PLAN_MATRIX|PLAN_TYPES|AI_RESPONSE_MODES|TRIAL_DAYS|aiCreditsMonthly|creditCost" lib/plans.ts`
- `rg -n "birds: 300|birds: 1000|users: 5|creditCost: 5" lib/plans.ts`
- `npm run build`

**Acceptance criteria:**
- `lib/plans.ts` exists and exports `PlanType`, `AIResponseMode`, `PLAN_MATRIX`, and AI mode costs.
- The module contains limits for birds, users, farms, tasks, insights, and AI credits for all three plans.
- AI mode costs are exactly 1, 3, and 5.

### 08-02-02. Add defensive plan and permission helpers

**Type:** implementation  
**Files:** `lib/plans.ts`  
**Read first:**
- `lib/plans.ts`
- `.planning/phases/08-plan-persistence-permission-matrix/08-CONTEXT.md`

**Action:**
- In `lib/plans.ts`, export these helpers:
  - `isValidPlan(value: unknown): value is PlanType`
  - `parsePlan(value: unknown): PlanType`
  - `getPlanOrNull(value: unknown): PlanType | null`
  - `hasMinimumPlan(plan: PlanType, minimumPlan: PlanType): boolean`
  - `canAccessCapability(plan: PlanType, capability: CapabilityKey): boolean`
  - `getRequiredPlan(capability: CapabilityKey): PlanType`
  - `getPlanLimits(plan: PlanType)`
  - `getAICreditCost(mode: AIResponseMode): number`
  - `isValidAIResponseMode(value: unknown): value is AIResponseMode`
- `parsePlan` must fall back to `DEFAULT_PLAN`.
- `getPlanOrNull` must return `null` for missing, null, empty, or invalid values.
- Capability helpers must use minimum-plan semantics.

**Verify:**
- `rg -n "function isValidPlan|function parsePlan|function getPlanOrNull|function canAccessCapability|function getAICreditCost" lib/plans.ts`
- `npm run build`

**Acceptance criteria:**
- Runtime helpers exist for strict validation, fallback parsing, and null invalid-plan detection.
- `parsePlan("bad")` would return `DEFAULT_PLAN`.
- `getPlanOrNull("bad")` would return `null`.
- Capability checks use plan ordering, not string equality chains.

- Existing imports of `usePlan()` keep compiling.

### Threats

- **High: Invalid persisted plan becomes trusted by TypeScript cast.** Mitigate by central parser and removing `as PlanType` from `PlanProvider`.
- **Medium: Commercial limit drift between landing page and app.** Mitigate by importing values from `lib/plans.ts`.
- **Medium: Capability names become route-coupled and hard to maintain.** Mitigate by product-facing capability keys with route metadata.
- **Medium: AI credit costs drift across UI/API.** Mitigate by central AI mode metadata and costs.

</threat_model>
