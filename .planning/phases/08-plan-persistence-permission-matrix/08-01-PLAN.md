# Plan 08-01: Profile Plan and Trial Schema Alignment

**Phase:** 8 - Plan Persistence & Permission Matrix  
**Status:** Ready  
**Requirements:** PLAN-01, PLAN-02, PLAN-03

<objective>
Align repository schema, migrations, profile creation, and TypeScript database types with the live `profiles.plan` source of truth and the required one-time 7-day Premium trial fields.
</objective>

## Scope

In scope:
- Add an idempotent Supabase migration for `profiles.plan` and trial timestamp columns.
- Backfill existing null/invalid plan data to `essencial`.
- Add or preserve allowed values `essencial`, `pro`, and `premium`.
- Update `handle_new_user()` so new profiles receive `plan = 'essencial'`.
- Update `supabase/schema.sql`, `supabase/migrations/00001_initial_schema.sql`, and `lib/database.types.ts` so fresh installs and TypeScript agree.
- Include a blocking schema push task.

Out of scope:
- Plan-selection UI; that is Plan 08-03.
- Central permission matrix; that is Plan 08-02.
- Stripe, billing validation, payment checkout, and subscription webhooks.

### 08-01-01. Add profile plan and trial migration

**Type:** implementation  
**Files:** `supabase/migrations/00014_profile_plan_trial.sql`  
**Read first:**
- `supabase/migrations/00001_initial_schema.sql`
- `supabase/schema.sql`
- `.planning/phases/08-plan-persistence-permission-matrix/08-CONTEXT.md`

**Action:**
- Create `supabase/migrations/00014_profile_plan_trial.sql`.
- Add idempotent SQL that:
  - Adds `plan text default 'essencial'` to `public.profiles` if it does not exist.
  - Adds nullable `trial_started_at timestamptz`, `trial_ends_at timestamptz`, and `trial_used_at timestamptz` to `public.profiles` if they do not exist.
  - Backfills `plan = 'essencial'` for rows where `plan is null` or `plan not in ('essencial', 'pro', 'premium')`.
  - Sets `plan` to `not null`.
  - Adds a check constraint named `profiles_plan_check` or equivalent enforcing `plan in ('essencial', 'pro', 'premium')`, dropping/replacing a stale same-named constraint if needed.
  - Replaces `public.handle_new_user()` so it inserts `id`, `email`, `full_name`, and `plan` with `plan = 'essencial'`.
- Keep the migration idempotent and safe to rerun.

**Verify:**
- `rg -n "trial_started_at|trial_ends_at|trial_used_at|profiles_plan_check|plan.*essencial" supabase/migrations/00014_profile_plan_trial.sql`
- `rg -n "insert into public.profiles .*plan|plan\\)\\s*values" supabase/migrations/00014_profile_plan_trial.sql`

**Acceptance criteria:**
- `supabase/migrations/00014_profile_plan_trial.sql` exists.
- The migration contains the literal strings `trial_started_at`, `trial_ends_at`, `trial_used_at`, `essencial`, `pro`, and `premium`.
- The migration updates `public.handle_new_user()`.
- The migration includes a check constraint for valid plan values.

<threat_model>

### Assets

- Persisted plan state in `public.profiles`.
- Trial eligibility and trial expiry state.
- New-user profile creation.
- Repository/live schema alignment.

### Threats

- **High: Invalid plan data bypasses intended plan selection.** Mitigate with database check constraint, `not null`, backfill, and runtime parsing in later plans.
- **Medium: Trial can be reused because expiry/use fields are missing.** Mitigate with explicit `trial_started_at`, `trial_ends_at`, and `trial_used_at`.
- **Medium: Repository schema drifts from live Supabase.** Mitigate by updating migration, schema snapshot, initial schema, types, and running schema push.
- **Low: Fresh installs get a different profile shape from migrated installs.** Mitigate by updating both `00001_initial_schema.sql` and the new migration.

</threat_model>
