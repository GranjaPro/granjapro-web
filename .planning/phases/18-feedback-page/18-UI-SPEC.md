# Phase 18 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none; use existing Tailwind dashboard patterns and local `components/ui` primitives |
| Preset | not applicable; `components.json` was not detected on 2026-07-19 |
| Component library | local React primitives only (`Button`, `Card`, `ModalPortal` where useful); Radix dependencies already exist but no new component registry is allowed |
| Icon library | `lucide-react`; use `Star`, `MessageSquare` or another existing Lucide feedback icon, and `Loader2` for submit loading |
| Font | Inter for all dashboard UI; do not introduce a new font |

This phase must render `/dashboard/feedback` as a quiet operational dashboard page. It is a work surface for an authenticated farm user, not a marketing page, hero page, or testimonial page. Reuse the existing dashboard shell spacing, white/slate surfaces, rounded controls, brand green focus states, and inline status banners.

Primary focal point: the feedback form card is the main visual anchor, with the star rating as the first interaction target and `Enviar feedback` as the strongest action target after rating/category selection.

Exceptions: none.

## Typography

Use exactly these four text sizes and exactly these two weights in the feedback page UI.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 600 | 1.4 |
| Heading | 16px | 600 | 1.25 |
| Display | 24px | 600 | 1.2 |

Rules:
- Field labels, helper text labels, category names, and validation labels use `Label`.
- Form body copy, textarea text, select text, inline errors, and confirmation body use `Body`.
- Card or section titles use `Heading`.
- Page title uses `Display`; do not use hero-scale type.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f8faf9` light, `#020617` dark | Dashboard canvas and page background |
| Secondary (30%) | `#ffffff` light, `#0f172a` dark | Form card, supporting panel, top bar-compatible surfaces |
| Accent (10%) | `#2d7a4f` (`brand-500`) | Specific reserved elements listed below only |
| Destructive | `#dc2626` (`red-600`) | Destructive actions only; not applicable to this phase except existing shared app chrome |

Accent reserved for: selected star fill/stroke, primary submit button, focus ring/border, active feedback sidebar item, profile modal feedback button icon/background, success confirmation icon or left border.

Status colors:
- Validation and submit errors use the existing red pattern: `bg-red-50`, `border-red-200`, `text-red-700` in light mode and matching dark red utilities already used by dashboard banners.
- Success confirmation uses brand or emerald status styling, but keep it quieter than the primary CTA.
- Category selector options do not each receive unique colors in this phase; categories are text values, not colored workflow statuses.

## Interaction Contract

| Area | Contract |
|------|----------|
| Route surface | `/dashboard/feedback` renders inside the existing dashboard layout with a constrained content column; no marketing hero, decorative background, or analytics/admin table. |
| Form fields | Rating is a 1-5 star control, category is a selector with exactly `Satisfacao`, `Bug`, `Sugestao`, `Dificuldade`, `Outro`, and description is an optional textarea. |
| Required data | Disable submit until authenticated `user.id`, active `farm.id`, rating, and category are present. Description remains optional. |
| Star rating | Stars are icon buttons with visible selected, hover, keyboard focus, and disabled states. Selecting a star sets the exact numeric rating. |
| Category selector | Use the existing rounded input/select pattern with brand focus ring; include a placeholder option that cannot be submitted. |
| Description | Encourage context with helper copy, but never block submit when it is blank. Trim whitespace before persistence. |
| Submit | Primary CTA is specific: `Enviar feedback`. While saving, disable controls and show `Loader2` with loading copy. |
| Success | On successful submit, show in-page confirmation, clear the form, and stay on `/dashboard/feedback`. Do not redirect. |
| Error | Show inline field errors for missing rating/category and an inline submit error banner for persistence/RLS failures. Every error message must include the next action. |
| Desktop sidebar | Add one link labeled `Feedback` at the end of the desktop sidebar navigation, after the existing report/AI-related items and before account/sign-out controls. |
| Profile Settings modal | Add one feedback button inside the existing modal pattern; clicking it closes the modal and routes to `/dashboard/feedback`. |
| Mobile nav | `components/layout/mobile-nav.tsx` remains unchanged; do not add feedback to the bottom navigation. |
| Out of scope | No admin review dashboard, submitted-feedback history, edit flow, delete flow, or destructive action UI. |
