# Plan 22-03: Gap Closure for Inventory UAT

<objective>
Close Phase 22 inventory UAT gaps by exposing storage location selection and total cost inputs in current feed/inventory forms, and by ensuring newly created feed items render from the specialized `feed_inventory` compatibility service.
</objective>

## Rationale
This plan addresses the implementation gaps identified during the UAT of Phase 22 (Storage Locations and Inventory Database). The gaps include missing inputs (cost, quantity, unit) in the inventory forms, missing location selection for feed registration, and overly strict filtering preventing newly added feed items from rendering correctly. Fixing these is required to pass the UAT and ensure the financial trigger creates expenses appropriately.

## Step 1: Fix Feed Page Inventory Form and Rendering
**Target:** `app/dashboard/racao/page.tsx`
**Action:** 
1. Update `loadData()` to also fetch `storage_locations` where `category === 'feed'` and store them in a new state variable `storageLocations`. (Use `getStorageLocations` from `@/app/actions/storage-locations` or a direct Supabase query).
2. When setting `inventoryData` from the fetch results, remove the `.filter(d => d.type === 'racao')` line. `getFeedInventory` already fetches only feed items, and the filter prevents new items with different casing or default strings from rendering.
3. In the inventory Add/Edit modal, replace the `<input type="text">` for "Local" with a `<select>` dropdown. Populate it with the `storageLocations` fetched earlier, and include a default option "Sem local definido" (which maps to `null` or empty string).
4. Add a new numeric input for "Valor Total (R$)" (Total Cost) to the Add/Edit modal. Bind this to a `total_cost` field in the form state variables.
5. Update the form submission logic to pass `total_cost` and the selected `location_id` (or location name, depending on the schema) in the API calls for creating and updating inventory items.
