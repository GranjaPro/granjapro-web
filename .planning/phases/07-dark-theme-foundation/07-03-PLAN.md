# Plan 07-03: Dashboard Page Cleanup and Theme Verification

**Phase:** 7 - Dark Theme Foundation  
**Status:** Ready  
**Requirements:** THEME-03, THEME-04

<objective>
Apply a selective dark-theme cleanup to high-traffic dashboard pages and verify that dashboard contrast, mobile/desktop behavior, and public/auth page styling remain stable.
</objective>

## Scope

In scope:
- Convert repeated light page surfaces in the main dashboard home and key dashboard pages.
- Tune chart tooltip/grid/tick colors where light inline styles remain unreadable.
- Convert shared dashboard widget components used on the home page.
- Run build/source checks and record manual visual verification targets.

Out of scope:
- Exhaustively restyling every nested details page if it is not practical in this phase.
- Changing data fetching, chart metrics, dashboard layout, or route behavior.
- Redesigning public/auth/legal pages.

<tasks>

### 07-03-01. Convert dashboard home and shared dashboard widgets

**Type:** implementation  
**Files:** `app/dashboard/page.tsx`, `components/dashboard/*.tsx`  
**Action:**
- Convert the highest-impact `bg-white`, `bg-gray-50`, `border-gray-*`, and `text-gray-*` surfaces on the dashboard home to dark-safe equivalents.
- Update KPI cards, quick actions, alerts, checklist, financial summary, barns overview, and production trend components as needed.
- Preserve data fetching, calculations, locked-overlay behavior, and layout density.
- Tune Recharts tooltip/content style on converted charts for dark readability.

**Verify:**
- `npm run build`
- Manual desktop and mobile scan of `/dashboard`.

**Acceptance criteria:**
- Dashboard home no longer reads as a light page inside a dark shell.
- Status cards and charts keep readable values, labels, and hover tooltips.

### 07-03-02. Convert representative operational pages

**Type:** implementation  
**Files:** `app/dashboard/production/page.tsx`, `app/dashboard/finances/page.tsx`, `app/dashboard/ai/page.tsx`, plus other touched dashboard pages as needed  
**Action:**
- Prioritize high-use and visually dense pages: production, finances, AI, barns, flocks, and sales.
- Use the shared conventions from Plan 07-01 instead of inventing page-specific palettes.
- Convert modals, tables, filters, empty states, and action buttons in touched pages where obvious light surfaces remain.
- Avoid broad blind replacement; inspect surrounding context before changing repeated utility classes.

**Verify:**
- `npm run build`
- Manual scan of selected routes on desktop and mobile.

**Acceptance criteria:**
- Key dashboard routes maintain contrast and focus states.
- Touched pages do not change workflow, data queries, or plan gating behavior.

### 07-03-03. Verify public/auth non-regression and document residual gaps

**Type:** verification  
**Files:** `.planning/phases/07-dark-theme-foundation/07-SUMMARY.md` when execution completes  
**Action:**
- Inspect `/`, `/login`, `/signup`, `/termos-de-uso`, and `/politica-de-privacidade` after global/dashboard theme changes.
- Confirm no public/auth page was intentionally redesigned.
- If some low-traffic dashboard detail pages still contain light surfaces, document them as residual visual debt instead of expanding scope unpredictably.
- Update `07-VALIDATION.md` frontmatter and status only after validation is complete.

**Verify:**
- `npm run build`
- Manual route checklist completed in the eventual plan summary.

**Acceptance criteria:**
- THEME-04 is checked explicitly.
- Any residual dashboard-only visual gaps are recorded with exact routes/files.

</tasks>

## Threat Model

### Assets

- Dashboard operational usability across routes.
- Public/auth page visual stability.
- Execution scope control.

### Threats

- **Medium: Broad utility replacement causes hidden route regressions.** Mitigate through selective changes and build/manual checks.
- **Medium: Chart inline colors remain light-theme-only.** Mitigate by inspecting/tuning chart tooltip, grid, tick, and active-dot colors.
- **Low: Public/auth pages change unintentionally from global CSS.** Mitigate with explicit non-regression inspection.

<verification>

### Automated checks

1. `npm run build`
2. `rg -n "prefers-color-scheme|Sistema|system" app components`

### Manual checks

1. Dashboard routes: `/dashboard`, `/dashboard/production`, `/dashboard/finances`, `/dashboard/ai`, `/dashboard/barns`, `/dashboard/flocks`, `/dashboard/sales`.
2. Modal/popover surfaces: profile settings, date filter, upgrade popup, locked overlay.
3. Public/auth routes: `/`, `/login`, `/signup`, `/termos-de-uso`, `/politica-de-privacidade`.
4. Mobile and desktop widths for shell, sidebar, top bar, content scroll areas, and buttons.

</verification>

<success_criteria>

- THEME-03 is satisfied for dashboard shell, navigation, modals, locked overlays, and common primitives.
- THEME-04 is verified for public/auth pages.
- Any remaining low-traffic dark-theme debt is documented rather than hidden.
- The phase is ready for execution without expanding into permission architecture.

</success_criteria>
