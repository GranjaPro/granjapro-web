# Debug: Feed Price Field Missing

## Issue
After adding a feed inventory item, checking the financial/expenses section shows an automatically generated expense transaction corresponding to the new item, but it is not possible to add the paid amount ("valor pago") when registering the feed inventory.

## Investigation
- Checked `app/dashboard/racao/page.tsx` for the feed inventory addition form (the "Adicionar Item ao Estoque" modal).
- The state `estoqueForm` tracks: `nome, categoria, quantidade, unidade, status, fornecedor, localizacao, lote, dataChegada`.
- There is no field for cost (`total_cost` or `unit_cost`) in the UI form.
- The `createInventoryItem` function in `lib/services/inventory.ts` accepts `unit_cost` and `total_cost`, which maps to `feed_inventory` table columns.
- Since the form has no input for the cost, `total_cost` is implicitly null when sending to `createInventoryItem`, which results in the backend trigger generating an expense of value 0.

## Root Cause
The `estoqueForm` and `editEstoqueForm` states and their respective UI inputs in `app/dashboard/racao/page.tsx` are missing a field for "Valor Pago" (Total Cost/Price). As a result, the feed inventory record is created without cost data, leading to a zero-value financial expense transaction being automatically generated by the backend trigger.

## Suggested Fix
1. Add a `custo` or `valorPago` field to `estoqueForm` and `editEstoqueForm` in `app/dashboard/racao/page.tsx`.
2. Add a UI input for this field in both the "Adicionar Item ao Estoque" and "Editar Registro" modals.
3. Update the `createInventoryItem` and `updateInventoryItem` calls to pass the new cost value as `total_cost` (and optionally calculate `unit_cost` based on quantity).

## Resolution
- Implemented as `valorTotal` in the feed inventory add/edit forms.
- Persisted through `createInventoryItem` and `updateInventoryItem` as `total_cost`.
- Verified with targeted `Select-String` checks and `npm run build`.
