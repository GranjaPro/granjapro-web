# Plan 07-01: Dashboard Dark Foundation and Shared Primitives

**Phase:** 7 - Dark Theme Foundation  
**Status:** Ready  
**Requirements:** THEME-01, THEME-03

<objective>
Make the authenticated dashboard deterministically dark at the shell boundary and update the shared primitive defaults that most dashboard surfaces inherit.
</objective>

## Scope

In scope:
- Apply an app-controlled dark dashboard mode without reading OS theme preference.
- Stabilize dashboard background, top bar, sidebar adjacency, loading state, scrollbars, and onboarding blur layer.
- Add dark-safe global/dashboard utility conventions.
- Update shared `Button`, `Card`, `Badge`, and `Progress` defaults to work on dark dashboard surfaces while preserving existing variant APIs.

Out of scope:
- Removing the profile preferences `Sistema` option; that is Plan 07-02.
- Broad page-by-page class replacement; that is Plan 07-03.
- Permissions, plan persistence, billing, or API guards.

<tasks>

### 07-01-01. Establish deterministic dashboard theme boundary

**Type:** implementation  
**Files:** `app/layout.tsx`, `app/dashboard/layout.tsx`, `app/globals.css`  
**Action:**
- Keep the root layout neutral for public/auth pages.
- Add a deterministic `dark` class or dashboard-owned equivalent at the authenticated dashboard shell boundary.
- Change dashboard shell backgrounds from `bg-[#f8faf9]`/white top-bar treatment to dark neutral surfaces.
- Ensure the loading state and onboarding blur layer look intentional on dark surfaces.
- Do not use `prefers-color-scheme`, `matchMedia`, `next-themes`, or OS system theme detection.

**Verify:**
- Source search shows dashboard dark behavior is class/app controlled, not system controlled.
- `npm run build` passes.

**Acceptance criteria:**
- Dashboard theme is dark regardless of OS preference.
- Public/auth pages do not receive a forced global dark class from `app/layout.tsx`.
- Sidebar, header, main content, loading state, and onboarding overlay are readable.

### 07-01-02. Add shared dark-safe surface conventions

**Type:** implementation  
**Files:** `app/globals.css`, `tailwind.config.ts` if needed  
**Action:**
- Add reusable dashboard utility classes only if they reduce repeated hardcoded color churn.
- Tune `dashboard-scroll`, `scrollbar-visible`, `scrollbar-chat`, and `onboarding-scroll` for dark backgrounds without breaking public scroll usage.
- Keep the palette restrained: dark neutral surfaces, brand green accents, and clear status colors.

**Verify:**
- Visual scan of dashboard scroll areas on mobile and desktop.
- `npm run build` passes.

**Acceptance criteria:**
- Scrollbars are visible enough on dark dashboard surfaces.
- Utility changes do not restyle public/auth pages unexpectedly.

### 07-01-03. Update shared UI primitives for dark dashboard defaults

**Type:** implementation  
**Files:** `components/ui/button.tsx`, `components/ui/card.tsx`, `components/ui/badge.tsx`, `components/ui/progress.tsx`  
**Action:**
- Add dark-safe defaults and focus states to Button variants.
- Make Card default surfaces work on dark pages while allowing page-specific overrides.
- Add dark-safe Badge and Progress variants/defaults without changing their public API.
- Preserve existing shape, density, and component names.

**Verify:**
- `npm run build` passes.
- Manual scan of dashboard cards, buttons, badges, and progress bars.

**Acceptance criteria:**
- Common primitives no longer force light cards or unreadable text on dark dashboard pages.
- Existing imports and variant calls keep compiling.

</tasks>

## Threat Model

### Assets

- Dashboard readability and navigability.
- Public/auth page visual stability.
- User ability to identify actionable status colors.

### Threats

- **Medium: Global dark class leaks into public/auth pages.** Mitigate by applying deterministic theme behavior at the dashboard boundary and checking public/auth pages.
- **Medium: Dark primitive defaults break pages still expecting light surfaces.** Mitigate by keeping APIs compatible and verifying the dashboard high-traffic surfaces before broad page conversion.
- **Low: One-note palette reduces operational scan quality.** Mitigate by retaining neutral surfaces, brand green accents, and distinct status colors.

<verification>

### Automated checks

1. `npm run build`
2. `rg -n "prefers-color-scheme|matchMedia|next-themes|system" app components`

### Manual checks

1. Dashboard shell loads dark on desktop and mobile.
2. Sidebar, top bar, main scroll area, loading state, and onboarding overlay remain readable.
3. Public/auth pages are not forced dark by root layout changes.

</verification>

<success_criteria>

- THEME-01 is satisfied for the dashboard shell.
- Shared primitives have dark-safe defaults for THEME-03.
- No system/OS theme behavior is introduced.
- Layout density and navigation structure remain unchanged.

</success_criteria>
