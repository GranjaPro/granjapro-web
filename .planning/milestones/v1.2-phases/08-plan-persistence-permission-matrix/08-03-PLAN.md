# Plan 08-03: Plan Selection and Trial Routing Foundation

**Phase:** 8 - Plan Persistence & Permission Matrix  
**Status:** Ready  
**Requirements:** PLAN-04, PERM-01, PERM-04, AI-03

<objective>
Add the minimal authenticated plan-selection flow that redirects missing/invalid/expired-trial users away from the dashboard, persists selected plans to `profiles.plan`, and grants a one-time 7-day Premium trial without Stripe.
</objective>

## Scope

In scope:
- Create a dashboard plan-selection page for authenticated users.
- Persist selected plans to `profiles.plan`.
- Start a one-time Premium trial with trial timestamps.
- Redirect invalid/missing/expired-trial users to plan selection on dashboard entry.
- Show matrix-driven plan limits and AI credit information on the selection page.

Out of scope:
- Real checkout, Stripe, billing portal, card collection, webhooks, or subscription validation.
- Full route/API guarding for every Pro/Premium route.
- Real AI credit consumption persistence.
- Replacing all existing locked overlays and sidebar gating.

### 08-03-01. Add plan/trial selection helpers

**Type:** implementation  
**Files:** `lib/plans.ts`  
**Read first:**
- `lib/plans.ts`
- `.planning/phases/08-plan-persistence-permission-matrix/08-CONTEXT.md`

**Action:**
- Add helper functions to `lib/plans.ts`:
  - `hasUsedTrial(profile: { trial_used_at: string | null } | null | undefined): boolean`
  - `isTrialActive(profile: { trial_ends_at: string | null } | null | undefined, now = new Date()): boolean`
  - `isTrialExpired(profile: { trial_ends_at: string | null; trial_used_at: string | null } | null | undefined, now = new Date()): boolean`
  - `requiresPlanSelection(profile: { plan: unknown; trial_ends_at: string | null; trial_used_at: string | null } | null | undefined, now = new Date()): boolean`
- `requiresPlanSelection` must return `true` when:
  - profile is missing;
  - `getPlanOrNull(profile.plan)` is `null`;
  - `trial_used_at` is non-null and `trial_ends_at` is in the past.
- `requiresPlanSelection` must return `false` for valid non-expired profile plans.

**Verify:**
- `rg -n "hasUsedTrial|isTrialActive|isTrialExpired|requiresPlanSelection" lib/plans.ts`
- `npm run build`

**Acceptance criteria:**
- Trial state helpers exist in central plan module.
- Expired trial profiles require plan selection.
- Missing or invalid plan profiles require plan selection.

### 08-03-02. Create authenticated plan-selection page

**Type:** implementation  
**Files:** `app/dashboard/select-plan/page.tsx`  
**Read first:**
- `app/dashboard/layout.tsx`
- `components/auth/auth-provider.tsx`
- `lib/plans.ts`
- `app/page.tsx`

**Action:**
- Create `app/dashboard/select-plan/page.tsx` as a client component.
- Use `useAuth()` to access `user`, `profile`, `refreshProfile`, and loading state.
- Render three plan choices from `PLAN_MATRIX`: Essencial, Pro, Premium.
- Each normal plan button must update the current profile:
  - `.from("profiles").update({ plan: selectedPlan }).eq("id", user.id)`
  - Do not set trial timestamps for normal plan selection.
  - After update, call `refreshProfile()` and route to `/dashboard`.
- Render a free trial action only when `hasUsedTrial(profile)` is false.
- Free trial action must update profile with:
  - `plan: "premium"`
  - `trial_started_at: new Date().toISOString()`
  - `trial_ends_at: new Date(Date.now() + TRIAL_DAYS * 24 * 60 * 60 * 1000).toISOString()`
  - `trial_used_at: new Date().toISOString()`
- After starting trial, call `refreshProfile()` and route to `/dashboard`.
- If the trial has already been used, show the trial action as unavailable or omit it.
- Show enough plan data from `PLAN_MATRIX` for the user to choose: display name, price, bird/user limits, AI monthly credits, and a note that Stripe/payment is not connected yet.
- Keep styling consistent with dashboard dark theme and mobile-first touch targets.

**Verify:**
- `rg -n "PLAN_MATRIX|TRIAL_DAYS|trial_started_at|trial_ends_at|trial_used_at|update\\(\\{ plan" app/dashboard/select-plan/page.tsx`
- `rg -n "Sem cartão|teste|7" app/dashboard/select-plan/page.tsx`
- `npm run build`

**Acceptance criteria:**
- `/dashboard/select-plan` exists.
- Normal plan choices persist `profiles.plan`.
- Free trial persists Premium and trial timestamps.
- Trial action is not available after `trial_used_at` exists.
- No Stripe checkout or fake payment validation is added.

<threat_model>

### Assets

- Dashboard access for users with valid plan state.
- One-time Premium trial eligibility.
- Profile plan persistence.
- User trust around no-card trial and no active Stripe integration.

### Threats

- **High: Invalid or expired-trial users still access the dashboard.** Mitigate with dashboard-entry redirect using central `requiresPlanSelection`.
- **High: Trial can be reused.** Mitigate by storing `trial_used_at` and hiding/disabling trial action when it exists.
- **Medium: Plan selection appears to be paid checkout when no Stripe exists.** Mitigate with clear no-card/no-payment copy and no fake checkout.
- **Medium: Redirect loop blocks plan selection.** Mitigate by exempting `/dashboard/select-plan`.
- **Low: UI hardcodes divergent AI credit costs.** Mitigate by iterating over central AI mode metadata.

</threat_model>
