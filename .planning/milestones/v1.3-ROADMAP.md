# Milestone Roadmap: v1.3 - Functional MVP & Integrations

## Summary
Complete database integrations, implement billing with Stripe Checkout, configure Gemini 1.5 Flash AI with RAG, build the feedback collection loops, re-architect and specialized the inventory system, and run pre-launch security tests before the end of July.

---

## Phases

### Phase 11: Stripe Checkout Redirect
- **Goal**: Implement api route `/api/checkout` to create Stripe checkout sessions for monthly plans ("Essencial", "Pro", "Premium") and redirect users from selection view.

### Phase 12: Stripe Webhooks & Plan Gating
- **Goal**: Build Stripe webhook endpoint `/api/webhooks/stripe` to update profile plans on checkout success, and secure premium routes.

### Phase 13: Feed and Water Logging
- **Goal**: Split feed and water management into separate pages, create the dedicated `water_consumption` table with RLS, gate `/dashboard/agua` to Pro/Premium users, connect feed comparison charts to real water data for Pro/Premium users, and integrate the 110g-130g daily feed target indicators on `/dashboard/racao`.

### Phase 14: Flock Water Details Page
- **Goal**: Connect flock water page `/agua` to display actual DB consumption metrics compared against developmental targets (55ml to 245ml/bird/day).

### Phase 15: Real Health History Page
- **Goal**: Connect flock health history timeline and list views directly to the `health_records` table, removing mock events.

### Phase 16: Flock Tasks CRUD
- **Goal**: Run migration adding priority, category, icon, and recurrence to `tasks`, and implement the dedicated CRUD view `/dashboard/tasks`.

### Phase 17: Dashboard Checklist and Alerts
- **Goal**: Hook home dashboard tasks checklist and alerts panel to live DB records from `tasks` and `alerts` tables.

### Phase 18: Feedback Page
- **Goal**: Run migration creating `feedbacks` table, implement `/dashboard/feedback` page, and add menu/profile modal access routes.

### Phase 19: Evaluation Triggers and Alerts
- **Goal**: Build usage-monitoring triggers that push dynamic notification cards asking active users to rate the platform.

### Phase 20: KPI Goals Persistence
- **Goal**: Create `kpi_goals` table, build customizable target modals on dashboard card clicks, and display built-in production quality loss limits (broken, dirty, deformed, internal).

### Phase 21: Gemini 1.5 Flash RAG AI Assistant
- **Goal**: Integrate Gemini 1.5 Flash at `/api/ai/route.ts` and feed the RAG contextually with all datasets of the active farm (barns, flocks, metrics, logs, transactions, tasks).

### Phase 22: Storage Locations and Inventory Database
- **Goal**: Run database migrations to create tables `storage_locations`, `feed_inventory`, `vaccine_inventory`, `packaging_inventory`, `inventory_losses`, RLS policies, and triggers for auto-expense logging and safe location deletions.

### Phase 23: Storage Locations and Feed UI
- **Goal**: Refactor `/dashboard/inventory` UI to remove Equipment filters, build storage location aggregate views, the Feed tab, and the modal flow for recording stock losses.

### Phase 24: Vaccines and Packaging UI
- **Goal**: Build UI tabs for Vaccines and Packaging, fully integrated with their specialized database tables and tracking expiration dates and batch data.

### Phase 25: Security and RLS Audit
- **Goal**: Audit Row Level Security (RLS) policies across all new and existing tables and validate Stripe webhook signature checks before deploy.

### Phase 26: Functional Farm Assistant
- **Goal**: Replace the mocked Farm Assistant component logic with a real implementation connected to the app's AI/API flow and farm data, preserving the existing UI contract and removing mock-only behavior.

### Phase 27: Flock Mortality Page Integration
- **Goal**: Connect the flock-specific mortality page `/dashboard/flocks/detalhes/[loteId]/mortalidade` to the Supabase database. Fetch real records for the specific flock, calculate real metrics and charts, and persist new mortality/culling logs to the `mortality` table.
